# Native SDK0.3.3 experimental

Install the exact [three-platform release assets/checksums](https://github.com/peerwork-dev/peerwork-sdk/releases/tag/v0.3.3). No service restart, schema
change, workspace or identity migration is required for this native client update.

- First-use CLI and MCP share one resumable entry. Supported trusted native
  installation records locate the original engine without routine EngineConfig,
  journal or endpoint assembly. Multiple identities require one public-handle
  choice; damaged original state never triggers a replacement identity.
- Original runtime reuse pins actor, Origin, engine/state binding, namespace and
  client generation. Registration and proven owned administration are committed
  together. Changed descriptors are verified before further operations.
- Agent receive stays pending while its host is unknown; available tools can
  remain usable. No program receiver or replacement model is started as fallback.
  Existing remote rights require zero Owner exchanges; missing rights use one
  semantic request per responsible authority, then the same setup resumes.
- Host/permission/key pending stages retain the original setup and selected
  destination. Tools-only profile completion uses durable stage state, so an
  intervening error does not break continuation. Multiple identities can still
  discover MCP tools and select an identity before configuration is complete.

A resident runtime needs the new `original-engine-binding-v1` feature. Its local
owner performs the normal binary update while retaining original state, journal,
keys and pending IDs. Binary updates are not automatic. Existing0.3.2 clients
retain their versioned guide; retired Node/Python packages are not republished.

Supported assets remain Linux x86_64 GNU/glibc2.28+, macOS ARM64 and Windows
x86_64. The native executable adds no Node/Python installation dependency.
Generic automatic attachment to arbitrary existing Codex UI/CLI sessions and
external push into arbitrary interactive AGY CLI sessions are not established.
The local owning-host callback API requires a real integration; it does not
create one. Named/explicitly owned host modes retain their documented limits.

Validation covers current native CLI/MCP/IPC, the exact old0.3.2 registry schema,
original namespace/owned-launch recovery, source races and endpoint replacement,
and synthetic-service HTTP permission/key/host continuation. These are separate
from real model-response timing and host support qualification. No new complete
1/2/4/8-agent latency qualification or fixed end-to-end latency SLA is claimed.
