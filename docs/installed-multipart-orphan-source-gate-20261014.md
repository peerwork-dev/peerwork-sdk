The test uses `tests/multipart-orphan-post-barrier.py` as a task-local HTTP forwarding origin. It arms only after attachment. The first new stage POST goes to the reference service. The second POST is read and held **before forwarding**, after the runtime's source-pinned save-before-transport step. The barrier retains only method, path and SHA-256 of the outbound body. Once the first part is signed, the driver terminates the CLI caller, confirms the second POST did not reach the service, and discards the held transport. A fresh Node process resumes via the public exact-ID replan API with no material file. The barrier compares the first retry's method, path and body digest to the withheld request before forwarding; mismatched bytes fail without service submission. This tests exact outbound signed-request reuse without reading the protected StageRow. The public attachment listing supplies the selected replan stage ID; it is **not** used for installation until a signed `ATTACHED`/`ORPHAN_REPLANNED` result and full SOURCE readback.

The fresh replan call may finish all remaining parts in the same call. If it returns the exact `ORPHAN_STAGE_UNRESOLVED` error, bounded public retries must reach `ATTACHED`. A dropped post-apply reply alone does not imply an unresolved status. The test verifies the original command still has no commit, total stage commit count is `2 + part_count`, each authenticated `protocol_package_part` matches the fixture's exact ID/index/hash, repeat replan adds no commit, and a Python private staged install using the new stage ID yields an authenticated protocol and instance. Same-ID install continuation must not add a commit. This is a **scripted mixed-interface** path; it does not establish independent complete Python/Node/CLI flows, natural Agent workflow compliance, Windows/macOS execution, or a general network capture claim.
