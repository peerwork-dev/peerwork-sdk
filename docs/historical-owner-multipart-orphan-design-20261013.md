# Historical Owner multipart orphan: source-backed next tranche

This is a design and fixture plan, not importer or service acceptance. The genuine f828 public `SecureAgentClient.stagePackageMaterial` saves `package_stage_intents[workspace.source_id]` immediately before calling `post` (`workspace-secure-agent.ts:184–197`). `post` saves `pending[command_id]={path,body}` before network (`:82`). A throw before the original second `post`, after part 0 has succeeded, therefore leaves marker index 1 with **no saved signed packet** for that marker command. The existing one-part `stage-marker-orphan` fixture stops at index 0; the existing multipart index-1 modes retain a packet, so neither proves this state. Native `verify_orphan_package_stage` currently rejects index != 0; the core material helper and `replan_orphan_package_stage` require one part/index 0. This is a product gap, not an accepted unsupported family.

The smallest genuine source fixture uses current pinned f828 PRIVATE wire-v3 STRUCTURED Owner and the existing >=3-part (150,000-character README) material. Wrap only the public client's `post`: allow part 0 normally, then at stage call 2 assert the signed `secure.protocol-package.stage` command and throw **before** calling the original `post`. Do not delete or modify local state or service rows. On close, require one signed ADMIN part at `source.sequence+1`, marker index 1 and original command ID, exact source ID/hash, `pending[marker.command_id]` absent, no matching service command, and unchanged count beyond the accepted prefix. Export protected state/PEM/intent paths and full material only through the task-local fixture; the native inventory must return safe metadata, not keys or packet bytes. A paired wrong-material candidate should compile to a different source ID with the same >=3-part shape. This fixture is setup evidence only until native attach/replan runs.

Pre-PREPARED authorization must bind the caller-selected original marker ID and complete TS-state/PEM/checked intent snapshot digests, authenticated Owner/key/ring/current PRIVATE ACTIVE policy, source checkpoint ancestry, and every signed prefix ADMIN part to the caller-supplied **full** material's canonical package proof. It must check complete replay for the marker command ID: if present, validate the exact signed operation/part as an applied historical part; if absent, retain uncertainty and never claim server-signed rejection or infer nonapplication from missing local `pending`. For the first fixture, latest head must be exactly the signed prefix end before permitting a fresh replan; a later head/policy/epoch change requires a separate explicit disposition, never an implicit rebase of the old source. Recheck original source digests before immutable PREPARED, keep external old-client quiescence as a prerequisite, and leave no attachment/lifecycle state on failed selection or material proof.

After an explicit protected attach/selection, expose `ORPHAN_NO_PACKET` and keep ordinary action/install/format selection restricted. The old marker, command ID, prefix and snapshot stay in protected history. `replan_orphan_package_stage` is a **new** authorization, not a retry of the missing packet: it must compile caller-supplied material at the *current authenticated checkpoint* into a distinct source ID and stage ID, persist that new source, full-material/proof digests and all chosen command IDs before their POSTs, and reuse the same saved ID/packet on cancellation, fresh handle and applied-response-loss. Use the existing producer's save-before-POST path under the attach root lock, with importer provenance excluding ordinary continuation. Only full signed replay of every new part and complete source proof may mark the old marker `ORPHAN_REPLANNED` and reopen normal selectors. Preserve the old local uncertainty; do not re-sign or synthesize its missing original ciphertext. A new install, if requested, follows the normal current-checkpoint wire rule independently.

The first bounded actual gate should cover inspect/select/attach with zero POST, wrong ID and different material before PREPARED, explicit fresh-source replan, cancellation after new durable step save, source-removed fresh-handle resume of the same new step, applied-response-loss reconciliation and full signed >=3-part completion. Assert preserved old marker/prefix and distinct new IDs, no duplicate effects, authenticated readback and exact retry. A marker command that appears later in signed replay, an intervening head, missing material, a changed Owner/key/policy/epoch, and other intent-map families remain separate required cases. Scripted service outcomes must not be reported as natural Agent workflow compliance.
