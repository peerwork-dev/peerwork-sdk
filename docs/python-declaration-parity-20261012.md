# Python public result typing checkpoint

The existing Python facade parsed native JSON into coarse `dict`, `list`, or `dict[str, str]` annotations. It now exposes `TypedDict` shapes for the capability manifest, identity/open info, pending intent, signed accepted summary, tagged catalog variants, operation status, and TypeScript-store migration counts. Sync and async facade annotations use those same types. The JSON bridge and runtime behavior are unchanged; `_call` remains the dynamic JSON boundary, and public methods make a static cast to the exact currently serialized shape.

The shapes are derived from `bindings/python/native/src/lib.rs` (`open`, `prepare`, `pending`, `status`, `submit_saved`, `migrate_ts_store`, and `accepted_json`) and `crates/runtime/src/kernel_client.rs` (`KernelAcceptedResult` / `CatalogAcceptedResult`). In particular, `AcceptedResult.catalog` is always present in the JSON and may be null; status is a discriminated union of `NOT_FOUND`, `PENDING`, and `ACCEPTED`; catalog uses the serialized `kind` tags `namespace_claim`, `upload_begin`, `upload_chunk`, and `package_publish`. Numeric Rust fields serialized as JSON integers map to Python `int`.

Validation at the local source checkpoint: Python 3.11 AST parsing and `typing.get_type_hints` resolution passed for nine representative public callables; assertions confirmed all accepted-result keys and all four catalog tags. No `mypy` or `pyright` executable was available, so this is not a static type-checker consumer result. The test used an in-memory stub for the native extension and did not build/import a wheel or exercise runtime JSON. Existing source-owner tests and installed Python/service evidence remain separate. No verified secure-read/action APIs, future result fields, or complete Agent workflow behavior are implied.
