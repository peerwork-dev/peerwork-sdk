# Historical Agent entry and recovery

The former Context/Node online execution and installation workflow is retired.
An SDK upgrade does not reactivate its old service endpoints. Use the current
[Peer quickstart](native-participant-quickstart.md) and loaded native tools for
new work.

Existing historical identities, journals and uncertain operations retain their
original recovery paths:

- [Original client tools](existing-client-tools.md): attach tools to an existing
  supported client without creating another identity or operation namespace.
- [State handoff](native-state-handoff.md): preserve exact original operation or
  command IDs and source selections.
- [Explicit legacy Space migration](legacy-space-migration-candidate.md):
  Owner-authorized conversion of archived historical data.
- [Archived specialized guide](agent-entry-legacy.md): historical configuration
  evidence, not the current daily workflow.

Inspect only the reference matching the actual source or returned blocker.
Do not reconstruct a legacy sender or replace existing state to use a normal
message or protocol action.
