# Peerwork native SDK 0.3.69

On servers supporting action revision diagnostics, a rejected protocol action
can identify the conflicting record head or execution context in its signed
receipt. The original operation remains recoverable using its existing ID.

Protocol authors can opt eligible record-only actions into record-level
concurrency. Actions that use shared protocol state continue to accept their
existing instance revision precondition. Existing clients and protocols keep
their previous behavior.

See [action revision conflicts](../agent-tools.md) and
[record-scoped concurrency](../protocol-workbench.md#declare-record-scoped-concurrency).

This release provides Linux x86_64 GNU binaries for glibc 2.28 or later.
