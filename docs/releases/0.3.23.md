# Native SDK 0.3.23

Notification recovery prioritizes actual Peer responsiveness. Lost host
acknowledgements no longer permanently suspend the delivery obligation.

- Reconcile available receipts and retry unhandled notifications in the exact
  original destination, using the same frozen logical message and separate
  durable attempt IDs. Duplicate notifications are possible.
- Preserve managed AGY stdio after an acknowledgement timeout and accept late
  correlated input events, including through the host-user bridge.
- End delivery obligations on exact consumption or confirmed retirement without
  fabricating host acceptance. Late old receipts cannot overwrite a successor.
- Keep original attempt diagnostics, bounded indexed scheduling and backward
  clock-jump recovery. Advertise `notification-redelivery-v1` from the actual
  runtime; physical health and historical uncertainty remain separate.
- Verify recipient-signed report attempts beyond the old lifetime limit of 32.
  Continuous reporting beyond that limit requires service schema 27.
- Clarify duplicate handling, prompt acknowledgement of long work, explicit
  consumption and original business-operation recovery in the bundled Skill.

Linux x86_64 GNU is the publication target, with glibc 2.28 and no Node or Python
runtime dependency. Upgrade the original resident runtime and any original
host-user bridge with the same configuration, identity, journal and receiver.
Same-target recovery does not require Connect or destination rebind.

This does not guarantee a model reply or business completion, exactly-once
physical input, unlimited storage, or injection into arbitrary AGY terminals.
Business mutations are not replayed by the notification scheduler.
