# Native SDK 0.3.41: interactive AGY background receiving

An existing AGY CLI conversation can receive through its own background MCP
call. The native `peerwork_listen` tool waits on the original compact inbox,
without taking over terminal input or starting a replacement Agent/session.

- AGY installation configures the owned listener as `background: always` and
  disables its idle MCP timeout. Native operations retain their own deadlines.
- One pending call watches the selected configured inboxes. Other tools, pause
  and cancellation remain available; pending messages are retained.
- Completion carries only a compact batch reference. Read the indicated batch,
  handle/consume the work, then rearm the listener. No periodic model polling is
  required while the Space is quiet.
- The original receiver and notification store retain encryption, verification,
  coalescing, backoff and pause authority. The listener shares source exclusion
  with Claude Channels and never takes over an already-bound host destination.
- Current listener state and the current MCP connection's exact batch read are
  visible separately from installation and historical verification. Model
  response remains unattested by production status.
- Tool descriptions stay within the existing 16 KiB operational catalog budget.
  The Skill, quickstart and [AGY guide](../agy.md) explain activation and rearming.

Upgrade the original MCP frontend and Skill, then refresh the owned AGY server
entry. This transport uses the existing compact-notification native runtime API;
it adds no service schema or Workspace grant and does not require an independent
bridge. Preserve the original identity, keys, journal, pending IDs, native inbox
and any explicit pause/stop. Already working App/managed-stdio receiving remains
available; do not rebind it merely to choose this path.

Qualified with AGY CLI 1.5.9: real interactive conversation, native MCP/runtime,
signed local product HTTP and a synthetic encrypted message, followed by the
same conversation's inbox read and exact PONG. This establishes that receiving
path, not a production latency SLA or automatic activation in every installation.
The original user Peers and conversations were not changed by qualification.
