# Native SDK 0.3.30

Repairs local notification ledger exhaustion without resetting identities,
journals, mailboxes, pending operations or host conversations.

- Service-confirmed consumption survives the receipt retry cache. Completed
  notifications retire across earlier sequence holes, including old uncertain
  host results, without inventing delivery or consumption facts.
- The Runtime shares one encrypted frozen frame per notification; the bridge
  retains binding/digest evidence instead of another rendered body. Consumed
  payloads release independently of pending compact reports.
- Monotonic attempt generations fence old requests while reported superseded
  retry/reminder evidence is reclaimed. Delayed callbacks cannot reopen completed
  work or overwrite the current attempt. Report pressure does not create an
  unbounded chain of new attempts.
- Already full legacy stores authenticate and compact bounded pages before new
  admission. Maintenance remains available at the admission limit. Invalid or
  unproven evidence is retained rather than silently discarded.
- Negative bridge receipts release unused reservations. Business-operation byte
  accounting includes retained resolved inputs and recovers old counters in
  bounded pages while preserving original input, outcome and command IDs.

Upgrade the original resident Runtime **and** host-user bridge using the same
state and destination. Update the MCP/CLI frontend and its installed Skill as
applicable. No service or Workspace permission change is needed. Real outstanding
work still has a finite capacity budget. Host acceptance, application consumption,
model response and business completion remain separate facts.

Qualification uses synthetic temporary state and authenticated loopback bridges,
including full legacy stores, a permanent early hole, receipt-window rollover,
80-attempt recovery, crashes/restarts, host-offline receipts and write contention.
This does not attest automatic delivery to an installed real model session.
