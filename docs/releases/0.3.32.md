# Native SDK 0.3.32 — fewer inbox calls and clearer local recovery

This patch repairs terminal inbox pagination and clarifies discovery reuse. It
also preserves the cause of local state failures through Connect and Claude
Channel without changing state protection or Workspace authority.

- A genuinely exhausted compact batch returns `more:false` without a
  continuation, including a final `limit:1` page and exact item/byte boundaries.
  Partial UTF-8 content and remaining selected scopes retain their exact
  continuation. Frozen batches exclude later arrivals; concurrent consumption
  does not authorize skipping to another delivery. Terminal detection uses
  bounded local lookahead, never a full backlog scan.
- Select the identity and Workspace once with `peerwork_context`, then reuse
  that selection and loaded tool schemas across ordinary wakes. A compact wake
  goes directly to its inbox batch without a context or status preflight. Refresh
  discovery after a real selection/binding change, loaded host/frontend upgrade,
  incompatible capabilities, explicit rediscovery, or loss of the selection.
  Current delivery questions use the existing status tool. Cached discovery
  cannot preserve revoked authority or establish permanent readiness.
- Local store failures retain compatible outer error families while carrying
  `details.local_state` with the cause, operation and next action. Contention,
  protection, I/O, corrupt/incompatible state, size and inherited-process faults
  no longer collapse into an undifferentiated ownership error. Connect open/save
  and Channel blocked-scope status retain the diagnostic. Error text does not
  disclose private paths or arbitrary OS messages, and contention does not
  invent a process owner.

Upgrade the original receiving runtime for the pagination repair and load the
updated frontend/Skill for the guidance and relevant local diagnostics. An
unchanged compatible bridge needs no replacement merely to match version
numbers. Preserve identity, journal, inbox, pending IDs, keys and exact host
binding; keep deliberately stopped or manually paused installations in that
state. No new Owner approval, receiver or persisted-state migration is required.
An older receiving runtime retains its earlier pagination behavior even if the
frontend executable has changed.

The runtime and cursor formats remain compatible with 0.3.31. This is a Linux
x86_64 GNU patch, with no new service/schema rollout, permission gate, completion
queue or automatic process updater. Existing status/recover still reconciles
the original operation. Host receipt, notification observation, application
consumption, model response and business completion remain distinct.

This release does not change presence refresh scheduling or Space retention.
It does not reclaim service capacity or claim that every Peer has upgraded.
Local fixtures and exact installed-artifact checks validate changed contracts;
actual reductions in Agent calls must be checked after adoption. Prior Codex and
managed AGY qualification used synthetic cached events; no new remote service
ingestion, authenticated Claude model wake, throughput or response SLA is implied.
