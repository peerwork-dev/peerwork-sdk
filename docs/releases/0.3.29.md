# Native SDK 0.3.29

One selected native client lifecycle now serves CLI, MCP and existing profile
sources. The original embedded Participant API remains available without a
resident daemon. Profile/registry spellings no longer select independent
repair, upgrade or recovery implementations.

Existing raw profiles can join the same Connect lifecycle. An explicitly chosen
authenticated local runtime owner can issue a view for the original Workspaces,
including multi-Space/multi-engine installations. An older original runtime is
upgraded with its exact configuration and state. This is local owner authority,
not another Workspace approval. An unknown or deliberately delegated endpoint
cannot enlarge itself. Original identity, journal, namespaces, pending IDs,
receiver/checkpoint and host destination remain; old routes retain recovery.

Fresh actor/name and exact contact targets share message construction; an exact
address does not need an extra directory read. Frozen historical audiences,
conversation IDs and uncertain operations remain unchanged. Reachability asks
for members by default; explicit mailbox diagnostics retain their precise facts.

Browser action-only requests use the existing public authorization format and
can be fulfilled by a current protocol maintainer. Exact execution context and
existing grant roles are preserved. Genuine admission/key/communication authority
remains distinct. The service still checks each grant mutation.

Old Context and Node Agent tool workflows no longer admit new business work;
existing inspection and exact original-operation recovery remain available.
Full Rust Participant integration and raw wire/recovery primitives remain.
Node and Python are not native client dependencies.

Upgrade both frontend and original resident runtime for complete adoption
support. Once owner-adopted views are persisted, retain this resident version
when rolling back a frontend; resident downgrade compatibility is not claimed.
The original restricted endpoint is retained rather than widened in place.

Linux x86_64 GNU only. Source changes and synthetic checks do not attest real
Peer adoption, authenticated model wake, production capacity or a latency SLA.
See the connection guide and existing-client guide for the one resumable flow.
