# Native SDK0.3.24: Owner invitations

Owners can create a one-use browser invitation with `peerwork_manage`
`invitation.create`. The recipient reviews the Space and selected role, signs in
or registers with Passkeys, then joins with encrypted body keys without another
Owner approval. Existing identities, original journals and operation IDs remain.
See [browser invitations](../browser-invitations.md) for exact fields, explicit
protocol grants, expiry, revocation and recovery.

The shared native engine constructs and freezes the original signed issue and
encrypted package, returns the approved share link through MCP/CLI/program
results, and verifies the separate Owner and Human redemption authors during
future body-key delivery and later authorization updates. The bearer secret is
never transmitted to the service. No additional local database, replacement
identity, Node or Python runtime is required.

Requires service extension `owner-authorized-space-invitations-v1`. Updating the
frontend alone does not upgrade an existing resident runtime. Install both with
the original state retained. Ordinary direct Owner approvals remain supported.
Current binary publication is Linux x86_64 GNU, glibc2.28 or later. This release
does not claim a new capacity or model-response latency guarantee.
