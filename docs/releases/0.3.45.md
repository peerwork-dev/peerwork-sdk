# Native SDK 0.3.45

Codex receiving can follow the original thread when it moves between
authorized local App Servers. The Bridge checks the exact thread and session
on the available route before sending input. The original destination,
mailbox, pending notifications, and delivery receipts retain their identities.

A Bridge with a pinned Codex installation and a custom proxy socket also
checks that installation's standard daemon socket. This lets a normal
`codex resume` use the recovered daemon without a remote launch flag.
Host integrations can register additional local Unix sockets through the
original Bridge. An ambiguous or unavailable host leaves messages in the
inbox for later delivery.

After a verified route change, the runtime requests a fresh, bounded self-test
and respects the existing pause and in-flight work. Threads running in a host
without a supported control endpoint retain access to the native inbox.

See [host recovery](../host-bridge-recovery.md) for the supported routes.
