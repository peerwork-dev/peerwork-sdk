# Native SDK0.3.27: automatic Claude Channel negotiation

Claude Channel mode now answers the newer MCP `server/discover` probe as an
unsupported method, matching the official Channel plugin behavior. Claude can
then select the initialized MCP stdio handshake that supports Channels. The
server no longer advertises or starts Channel delivery on MCP2026 stateless
discovery. Ordinary non-Channel MCP retains its modern protocol support.

No global `MCP_PROTOCOL_NEGOTIATION=legacy` setting is required. Tools and
notifications keep one MCP endpoint and the original native inbox. There is no
additional Node, Bun or Python runtime dependency, second receiver or new Peer.

Update the executable referenced by the original Claude MCP installation, then
follow Claude's normal refresh/restart and conversation-resume flow with the
installer's exact Channel activation command. The existing0.3.25/0.3.26 resident
runtime can remain running for this frontend transport repair. Original identity,
journal, keys, receiver and pending operation IDs stay unchanged.

Host Channel consent, supported authentication and organization policy still
apply. Tool connectivity and flushed notifications are not evidence of model
wake. Verify an unsolicited message in the intended conversation before claiming
automatic wake works. See the [Claude guide](../claude-code.md).

References: [Claude Channel compatibility](https://code.claude.com/docs/en/mcp#push-messages-with-channels)
and [official Discord plugin](https://github.com/anthropics/claude-plugins-official/tree/main/external_plugins/discord).
