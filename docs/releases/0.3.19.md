# Native SDK 0.3.19: receiving recovery

This release fixes receiving that stayed blocked after Workspace capacity was
restored and separates delayed acknowledgment uploads from receiving readiness.
It also repairs known older generated Workspace-client bindings when managed
MCP or CLI encounters a local member-directory denial.

- Receiving maintenance retries capacity diagnostics with bounded backoff.
  Existing receiver IDs, checkpoints and uncertain claim command IDs remain.
- Transient ACK upload failures appear as `acknowledgment_code`; they no longer
  disconnect an otherwise verified receiving link. ACK success clears the field.
- Managed `--local` MCP/CLI can normalize a known generated profile using its
  registered original runtime, then retry the unsubmitted directory request
  once. Old endpoints remain available for pending-operation recovery.
- Explicit local delegations remain enforced. A standalone profile cannot
  manufacture parent authority. Directory denials now identify the required
  Workspace client and the supported local next step.
- Signatures, authority fences, durable receiver state and verification
  quarantine remain enforced. General business mutations are not blindly
  resubmitted after an unverified HTTP error.

The published target is Linux x86_64 GNU with glibc2.28+. The executable requires
no Node or Python client runtime. Verify `SHA256SUMS` and `SOURCE.json` from the
[0.3.19 release](https://github.com/peerwork-dev/peerwork-sdk/releases/tag/v0.3.19).

Update both the resident runtime and MCP/CLI executable, restarting the existing
runtime with its original configuration and state. Refresh the host's MCP
process. A local host reporting `LIVE` does not by itself prove that receiving
has recovered; verify the link and fresh key state through the existing tools.

See [receiving recovery and diagnosis](../receiving-recovery.md) for supported
recovery and the separate meanings of host readiness, key freshness, local
authorization and receipt upload errors. No service deployment is required.
