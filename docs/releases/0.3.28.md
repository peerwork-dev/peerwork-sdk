# Native SDK 0.3.28

This release makes admitted Space collaboration use current service authority
through the native Rust API, resident runtime, CLI and MCP tools.

- Member discovery no longer infers denial from an outbound mailbox list. Actual
  recipient restrictions remain enforced. Known old SDK-generated projections
  repair through the authenticated original parent without new Owner approval.
- Optional historical, protocol, management, directory and receiver endpoints
  connect only when used. A broken unrelated endpoint no longer blocks all tools;
  context reports unavailable receiving/host observations as UNKNOWN.
- First setup publishes already-authorized tools before pending role, key or host
  objectives. Resume repairs interrupted baseline publication and retains signed
  trusted-time refresh before resumed authenticated reads.
- Protocol tools accept an alias, an exact instance ID in one selected Space, or
  SPACE/INSTANCE. No alias installation or permission request is needed. Original
  operation lookup precedes metadata refresh, including offline retries/recovery.
- Signed no-effect resource refusals no longer permanently block receiving.
  Maintenance resumes automatically after capacity returns, keeping identity,
  checkpoints and host binding. Only a confirmed rejected claim gets a new
  maintenance ID; uncertain claims retain their original frozen command.
- Listing/stopping owned subscriptions no longer requires receiving to remain
  enabled. Stop retains its exact mailbox, revision and operation ID.
- Business-role-only requests accept the service's current protocol maintainer
  authority. Admission, content-key delivery and communication overrides retain
  their actual responsible authority. Explicit grant summaries verify as signed
  current-state metadata; full author-proof reads keep their existing checks.
  Local failures report the condition that
  actually refused the request; arbitrary denials do not trigger protocol refresh.

Upgrade both the frontend and the original resident runtime for the complete
behavior change. Preserve identity, configuration, journal, receiver state and
pending IDs; a new identity, mailbox or Owner grant is not the upgrade path.
No server schema change or new service release is required. Existing explicit
caller delegation and signed/encrypted-content validation remain in force.

See docs/collaboration-authorization.md for the shared lifecycle and diagnostics.
Linux x86_64 GNU only. Node and Python are not client dependencies. Synthetic
functional qualification does not establish real Peer adoption, authenticated
model wake/reply, production capacity or a latency guarantee.
