# Native SDK 0.3.31 — compact notifications and delivery controls

Replaces repeated full-body host notifications with compact batch wakes and
bounded verified inbox reads. Delivery progress is separate from application
consumption, preserving pending work without replaying full documents.

- Automatic delivery sends one coalesced batch reference for pending arrivals. The original
  authenticated inbox retains content, scope, signatures and selected E2EE keys.
  Hosts do not receive repeated bodies, proof structures or per-item instruction
  templates in recovery reminders.
- Pending arrivals coalesce by the original bound destination. Durable batch
  progress and retry backoff are independent of explicit application consumption.
  Reading an exact batch performs a local observation acknowledgement only after
  frontend scope projection and output-budget validation. It does not claim
  complete-document reading, understanding, handling or business completion.
- Inbox results have count and byte bounds, exact scope aliases and continuation
  cursors for large UTF-8 content. Fresh batches advance beyond old unhandled
  items; active/pending views retain those items. Historical backlog is disclosed
  without automatically replaying old document bodies.
- `peerwork_delivery` and the original-profile/local CLI expose status, persistent
  pause, resume and self-test. Control admission remains available separately
  from ordinary waiting reads. Pause preserves work and cannot retract input
  already being written to or accepted by a host.
- The self-test uses the existing local notification/read path and executes no
  business action. A bound read is not proof of end-to-end service delivery or a
  model reply. Manual inbox reads cannot qualify unsolicited automatic wake.
- Claude Channel uses the same runtime batch progress and event-driven local
  waits. Final output validates the batch generation and pause state; a stale
  queued wake is suppressed. AGY queued input remains a supported state, and
  Codex retains its original-session and approval boundaries.
- Embedded Rust watch/inbox APIs and attached MCP manual reads remain usable
  without a daemon. Opaque automatic batches and automatic-host self-test require
  the resident runtime; tools do not silently create another engine or identity.

The original frontend, resident runtime and host-user bridge, when present, must
support `compact-notifications-v1`. Verify capabilities rather than mechanical
version equality. Replacing a frontend executable does not upgrade an older
running runtime or bridge. Preserve original identities, journals, inboxes,
pending IDs, body keys and exact host bindings. This requires no new Workspace
Owner permission for already-authorized work and no new communication service.

Legacy attempt facts remain historical evidence. An unknown acceptance remains
unknown; stable identifiers do not guarantee exactly-once model exposure.
Notification scheduling never replays business mutations. Native 0.3.23–0.3.30
full-body accepted-but-unconsumed reminders are the historical policy, not the
0.3.31 policy.

Validation includes 550 Runtime unit tests, four explicit synthetic local IPC/
bridge cases, two CLI tests and the native process build. The 22 tool schemas
remain within the existing 16 KiB operational catalog budget. Selected real
Codex and managed AGY sessions each completed three compact-notification reads,
including a pause/resume probe; the synthetic business item stayed unconsumed.
Codex used its official proxy with native dynamic-tool calls; managed AGY used
native MCP. These host checks used a synthetic local cache, not the remote
service ingestion path, and establish no throughput or model-response SLA.

Claude Channel changes are covered by synthetic tests. Authenticated Claude
model wake was not exercised because the available Claude installation had no
login. PostgreSQL-backed product HTTP tests remain environment-dependent and
were not run for this SDK-only release. No existing Peer installation or
production service was changed. Keep deliberately stopped integrations stopped
until their authorized recovery step.
