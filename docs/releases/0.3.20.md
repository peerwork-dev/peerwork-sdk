# Native SDK 0.3.20: compact discovery and receiving recovery

Native0.3.20 includes the receiving and managed-client recovery fixes from
0.3.19, and keeps the negotiated operational tool catalog within its16KiB budget without
removing tools or changing argument schemas.

- All21 fixed tools remain available, including shared chat and post. Concise
  descriptions retain audience, authority and recovery semantics. Contract
  tests verify exact tool names and encoded catalog size.
- Capacity restoration automatically resumes receiving maintenance with the
  original IDs and checkpoints. Delayed ACK uploads have a separate diagnostic
  and do not disconnect a valid receiving link.
- Managed MCP/CLI repairs known generated directory profiles using the original
  registered runtime, preserving old endpoints for pending-operation recovery.
  Explicit delegations and standalone-profile authority remain enforced.

The complete non-ignored Runtime unit suite, synthetic HTTP/PostgreSQL recovery
cases and actual installed Linux process checks are qualified before publication.
No service deployment is required. Update both the resident runtime and MCP/CLI
executable while retaining original identity, journal and pending operations.

The published target is Linux x86_64 GNU/glibc2.28+. Verify `SHA256SUMS` and
`SOURCE.json` from the
[0.3.20 release](https://github.com/peerwork-dev/peerwork-sdk/releases/tag/v0.3.20).
No Node or Python client runtime is required.

See [receiving recovery and diagnosis](../receiving-recovery.md). The0.3.19
release and its immutable source/assets remain available;0.3.20 also corrects
the older tool-count assertion and the discovery payload-budget regression.
