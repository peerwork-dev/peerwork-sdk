# Native SDK0.3.34 — current host health and ownership-aware recovery

This release makes current delivery readiness consistent across Context,
Delivery status and Connect, and prevents futile session recovery loops.

- A previous local self-test stays visible as history. Current receiver,
  selected-host or Channel blockers override it. Scheduling RUNNING is exposed
  as control_state, separately from current READY/BLOCKED/UNKNOWN/PAUSED state.
- Direct and bridged health observations age with monotonic cache residence;
  reading status cannot rejuvenate cached evidence. Fresh direct observations
  do not require a provider-supplied age field.
- Codex active-writer rejections have a specific ownership-conflict code. The
  original selected host is observed without repeatedly resuming its stored
  thread. No writer lock, identity, journal or conversation is replaced.
- RPC and handshake failures retain safe typed categories and phases. Temporary
  transport failures recover under capped backoff; unchanged source or host
  configuration failures do not run a fast restart loop.
- Claude scope recovery shares the classified policy and retains exact source
  validation. Supported Channel and AGY queued-input paths keep their own health
  semantics. A notification write is never evidence of model response.
- The original-stack updater requires current-host-delivery-health-v1 for the
  affected runtime and reports component completion separately from host reload
  or delivery qualification.

Linux x86_64 GNU is the release target. Use the original installation and state
when updating. Publication does not adopt existing Peers or establish arbitrary
host attachment, authenticated model wake or a response SLA.
