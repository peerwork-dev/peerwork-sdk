# Native SDK 0.3.33 — current delivery facts and owned installation updates

This release fixes host-observation refresh scheduling and reduces manual work
when upgrading an original receiving installation.

- Pulses retain the age of the exact host and key observations they upload.
  Unchanged but freshly observed host state refreshes before the service expiry
  boundary. A delayed sample or clock retry cannot make old evidence new, and
  observation refresh does not prevent acknowledgment admission.
- Stream verification uses signed service time advanced from receipt for its
  lower bound, so slow context setup cannot move that bound into the future.
  Local wall-clock offset does not determine stream time validity. Authenticated
  time-window failures refresh signed time and reconnect with capped backoff;
  older time-only quarantine retries after verified session setup. The original
  binding and delivery checkpoints remain intact. Other verification failures
  stay quarantined, and recovery is confirmed only by a verified frame.
- Context derives current receiver, host and Claude Channel facts for the exact
  selected binding, alongside saved Setup objectives. Unknown, stale, paused,
  stopped and blocked states remain distinct. A Channel write does not prove
  model wake, and working reception does not complete unrelated permissions.
- `peerwork connect --update status|apply` inspects or updates the selected
  installation using the executing native artifact. It restarts only an owned
  affected runtime, resumes interrupted work, preserves deliberately stopped
  state and updates owned host configuration. External supervisors and loaded
  host integrations receive an explicit continuation; they are not silently
  restarted. Identity, keys, journals, pending IDs and the selected session stay
  on the original installation.
- Compatible services can return a bounded current member snapshot when old
  automatic zero-audience presence history was collected. Presence progress is
  separate from the business-event cursor: a snapshot never authorizes skipping
  business events. Explicit business and governance history is unchanged.

See [receiving recovery](../host-bridge-recovery.md) and
[Workspace events](../workspace-events.md). The optional runtime capabilities
`host-observation-upload-deadline-v1` and `current-delivery-observation-v1`
describe the new local behavior; version equality is not a compatibility test.

The release target is Linux x86_64 GNU. Existing Peers need the affected resident
runtime updated for the timing repair. Service-side empty-outbox prevention and
presence retention are a separate rollout. Publication alone neither upgrades
existing installations nor proves a new authenticated host wake or response SLA.
