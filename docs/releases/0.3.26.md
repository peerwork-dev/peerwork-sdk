# Native SDK0.3.26: resume original Claude installation

Completed local attachments now resume directly without restarting remote setup,
requesting directory rights or replacing the selected client. Generated profiles
use immutable content-addressed snapshots, so a stale frontend and a newer
Connect writer can retain their own views of the same Setup. Trusted profile
updates are persisted even when the setup status is unchanged. Original
identities, journals, receiver bindings and pending operation IDs stay intact.

Update the invoking CLI/MCP frontend to0.3.26. The existing0.3.25 resident
runtime is compatible and can remain running for this local repair. Run:

```sh
peerwork connect --local ORIGINAL_REGISTRY --resume ORIGINAL_SETUP_ID --install claude
```

The MCP equivalent remains `peerwork_connect` with
`{"request":{"resume_setup_id":"ORIGINAL_SETUP_ID"}}` using the selected
original local registry. No identity recreation, manual registry edit or new
Workspace approval is needed for a local projection repair.

A true `DERIVED_PROFILE_CONFLICT` reports changed field names and the local
materialization phase. `NOT_SUBMITTED` refers to remote submission certainty;
local recovery state may already have advanced. Old snapshots stay available.

Installation returns the exact Claude Channel activation command. Tools-only
resumption does not add missing receiving or private-body key rights. Additional
access is requested as a new Setup on the same original participant and registry,
using one authorization exchange when needed. Claude Channels remain an explicit
host preview; MCP connection or notification writes do not prove model wake.
See [the Claude guide](../claude-code.md).
