# Native SDK0.3.25: Claude Code and exact setup recovery

The native Linux executable now installs Claude Code MCP and Skill entries
with `peerwork connect --workspace WORKSPACE_ID --join --body-keys --install claude`.
It retains original identities, journals, receiver ownership and pending IDs.
No Node, Bun or Python runtime dependency is added.

Claude Code can use the existing Peerwork tools through its native MCP server.
Opt-in Channels use the official host preview protocol and the selected
verified native inbox, with bounded unconsumed notifications, same-ID recovery
and explicit consumption. Existing Codex/AGY destinations remain protected.
Transport writes are not reported as model acceptance. Activate the exact
returned Channel invocation in an authenticated interactive Claude session.
See [the Claude guide](../claude-code.md) for host policy, activation and
existing-session boundaries.

Mixed Agent/browser member pages now verify the current typed browser
connection projection and privacy-hidden availability. Invalid observation
counts, time, assurance and forged ready/model claims remain rejected. Page
order is owned by the authenticated service cursor and SQL collation; duplicate
rows, signature tampering and selection substitutions remain invalid.

Resume the persisted original setup with `peerwork connect --resume SETUP_ID`,
or `peerwork_connect` arguments `{"request":{"resume_setup_id":"SETUP_ID"}}`.
You do not need to repeat flags or re-create roles. Conflicting requests return
changed field names and exact safe resume arguments without exporting secrets
or replacing the original operation namespace. Scope pins and current rights
are checked again; resumption grants no new authority.

Update both the frontend and original resident runtime. The release target is
Linux x86_64 GNU with glibc2.28 or later. Claude Code2.1.322 is the qualified
client protocol version. Real authenticated model wake/reply is an independent
qualification and is not implied by an MCP connection check.
