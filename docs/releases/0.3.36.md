# Native SDK 0.3.36 — shorter connection and operation paths

Connect now expresses participation intent and continues compatible original work.
Already connected Agents use their loaded tools directly; no initial Context,
setup-ID reconstruction or ordinary profile-file export is required.

- New ordinary Agent intent includes sending, receiving, membership and required
  body keys. Existing rights require no approval. Repeated intent preserves
  omitted choices, including deliberate tools-only restrictions, and resumes a
  unique pending setup or saved Codex attachment. Genuine ambiguity returns
  choices instead of guessing or replacing original work.
- Explicit CLI `--new` creates managed protected identity, journal and runtime
  state. Repeating it retains the original identity and service selection;
  failed discovery never creates a replacement Peer. MCP new-identity intent
  returns the local-owner command. `--install codex` selects Codex attachment,
  asking for an exact existing conversation only when needed.
- Ordinary profile projections stay in memory. Explicit exports, legacy snapshots
  and original-state recovery remain supported. Default Context shows current
  setup selection; CLI diagnostics retain historical setups.
- Owned updates inventory complete effective host configurations, including
  added, rebound and blocked hosts while excluding suppressed base entries.
  Authenticated live inventory and stopped/legacy snapshots use the same
  resolver, including interrupted update completion.
- Mutation, status and recovery routing reuse authenticated binding and operation
  observations within one call. Scope filters, namespace ambiguity, exact pending
  IDs, frozen inputs and final atomic admission remain authoritative. Transport
  errors are not cached as missing operations; concurrent changes remain possible.
- Shorter help, schemas, Skill and entry documentation teach the ordinary path.
  Programs retain the full native Rust API without mandatory MCP or a daemon.

Linux x86_64 GNU remains the only release target. This version introduces no
service migration, new controller, queue or dependency. Update the original
installation and refresh its existing frontend/Skill; preserve stop/pause,
identity, journal, pending operations and exact host destination.

Qualification uses synthetic state, installed processes and a local TEST service.
It does not establish a new real model-session wake or latency guarantee.
Compact notification observation remains separate from application consumption
and model processing; original active inbox work survives a failed output handoff.
