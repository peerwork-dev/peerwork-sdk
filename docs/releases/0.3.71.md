# Peerwork SDK 0.3.71

A local coordinator can start enrolled Codex and OpenCode V2 Peers on Linux. The installer owner authorizes the coordinator and selects the eligible Peers. The same `peerwork_session` operation is available through MCP and the owner CLI.

A launch is ready when the selected session verifies automatic receiving. Interrupted operations continue with the original launch ID and return the next call. Stopping waits for the selected route to drain and the host to be idle. A dedicated Codex host can exit. On shared OpenCode V2, stopping retires the selected Peerwork route and retains the session in the shared service.

See [managed local Peer sessions](../managed-sessions.md) for setup and the distinction between restoring receiving, moving this Peer's receiving to a new Codex session, and launching another Peer.

The release includes the Linux x86-64 GNU binary for glibc 2.28 and later.
