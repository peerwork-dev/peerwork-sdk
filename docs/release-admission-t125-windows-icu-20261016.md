The Windows ICU collation check in run [38838786286](https://github.com/peerwork-dev/peerwork-sdk/actions/runs/38838786286) failed with five `LNK2019` unresolved ICU symbols. Its archived diagnostic showed all three expected native archives present and all five expected symbols in the source archives, but did not establish whether Cargo bundled those objects into the `peerwork_core` rlib or whether the final MSVC link selected them. The run also showed the GNU core suite passing 104 tests, with the original replay regression passing; separate runtime failures are tracked by the runtime owner.

The first diagnostic run after commit `518159cf` completed Windows job `116802184617` with the same five LNK2019 errors. It confirmed all five expected names in the source archive public indexes and showed the failing reference came from `libpeerwork_core-...rlib`. The current rlib diagnostic printed `SYMBOLS_NONE`, but did not retain `dumpbin`'s exit status, so that result alone does not prove the rlib lacks the symbols. The run showed three rustc commands: the `peerwork_core` library, its test harness, and the `e2ee` integration test using `peerwork_core`; all reported ICU search paths. The `/VERBOSE:LIB` filter found no matching lines, but the first diagnostic did not report whether the flag reached the linker.

The follow-up candidate adds explicit status and bounded output for rlib `dumpbin`, plus per-command `-bundle` and `/VERBOSE:LIB` flag facts. It also changes only the Windows/MSVC `rustc-link-lib` directives to `static:-bundle`, registering the three native archives for the final consumer link rather than placing their archive members inside the Rust rlib. This is a bounded candidate hypothesis, not a confirmed root cause. The original core ICU test and integration consumer remain in the workflow; no test target is skipped. The GNU and macOS build-script paths are unchanged.

Validation: `git diff --check` passed. No local Windows/MSVC execution or PowerShell workflow execution was available, so the candidate and downstream native consumers remain unverified pending the hosted Windows job.
