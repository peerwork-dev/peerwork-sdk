## Existing facilities and supported facts

The f828 integration's `business-metrics.ts`/`search-attribution.ts` collect opt-in authenticated lexical task-result pages and same-agent participation. `operational-metrics.ts` counts process HTTP/status/latency and health. Neither collects protocol journeys, exact catalog→installation associations or evidenced controllers; neither supplies MET-01's denominator. Reuse their null/unavailable and aggregate-only conventions, not their tables or counts. No reusable acquisition collector was found in the SDK or these bounded current sources.

| Surface | Supported fact | Limit |
| --- | --- | --- |
| Catalog `search` / `inspect_exact` (`inspectExact`) | Catalog origin; exact digest checked against package-canonical bytes; public summary | Search does not establish intent, applicable authority or adoption; digest is not publisher trust |
| PUBLIC installer `begin` / `continue_install` (`continueInstall`) / `pending` | Explicit closure, bindings and expected package/protocol pins; protected BEGIN; signed-reconciled ACCEPTED progress and instance | PUBLIC journal lacks catalog namespace/version lineage; runtime digest alone cannot identify a release |
| Verified workspace `read`; public actions `submit/status/retry` | Signed replay sequence/head, installed instance/protocol and accepted action receipt | Objects/effects and private workspace IDs must stay outside the observation ledger; a receipt alone is not useful task acceptance |
| Kernel accepted catalog publication / exact catalog readback | Signed publication receipt and later visible exact bundle | Receipt and visibility are separate; no recipient delivery follows from a returned link |

Opaque caller-supplied principal/journey/task/evidence references join observations. No key, IP or device-based principal grouping. Distinct controllers, external status, consent, historical first-use and task acceptance require their own evidence; the collector cannot manufacture them.

## Product scope and explicit interface

Add one local acquisition module, with a common native schema/append/export/scorecard implementation and thin Python sync/async, Node typed and CLI access. Opening it requires an explicit local destination and caller observation context. Existing SDK constructors, calls and process environment acquire no default logger, listener, network upload or background job. Reading/exporting is on demand. A participant can use every SDK operation without using this module.

Proposed public primitives are `open_acquisition_observations(config)`, `append(event)`, `record_catalog_result(context, result)`, `record_install_result(context, release_selection, result)`, `record_action_result(context, result)`, `export()` and `scorecard(window, as_of)`, with camelCase Node equivalents and `observations append|export|scorecard` CLI parity. Adapters extract only allowlisted fields from existing public SDK results; they never serialize full result objects. Caller observations of qualifying start, deliberate new/existing selection, acceptance predicate, publication visibility, delivered share, coverage end and corrections use `append`. No synthetic observer is silently inserted into existing business calls.

Result adapters are supported observation helpers, not authentication of arbitrary caller JSON. `sdk_reported` facts, independently checked evidence and caller assertions stay distinguishable. Counting requires the declared evidence-verification/binding status; a caller-marked external flag or a signed actor alone cannot establish an eligible external principal. Evidence verification/acceptance remains local to the authorized observer or declared task predicate, not a mandatory central reviewer.

Required event fields follow the existing envelope exactly: event ID, occurred/observed UTC time, environment/audience class, opaque principal plus binding/newness status, journey/task/logical operation/attempt, stage/outcome, first-attempt/recovery, evidence reference and observer/version. Unknowns are null. Optional exact public release tuple, bundle/runtime digest, opaque instance, entry channel/reference, acceptance-predicate reference, finite error, measured duration/calls/tokens/cost/units, and observation end/coverage use bounded typed fields. Stage vocabulary includes all ten specified transitions and separate correction/withdrawal/conflict records. No prompts, queries, task bodies, messages, material, keys, raw authenticated responses or private workspace IDs enter storage/export. Evidence references are opaque references into a separately protected evidence store.

Explicit append uses the SDK's existing protected-parent/permissions/locking conventions, atomic transactions and configurable record/store bounds. Export reads a coherent snapshot; no record is rewritten or silently removed. Same event ID and same normalized payload is idempotent. Same ID with different payload is retained as a conflict observation and quarantines both candidates from metrics. Logical operations collapse retries for funnel counts while retaining every failed attempt. Corrections/withdrawals append references to prior events; unresolved contradictions remain unknown. Bounded failures are typed and do not change the underlying installation/action outcome. The schema rejects unknown fields, arbitrary extras and unbounded/raw payloads; claimed or unknown verification never upgrades external eligibility.

## Exact adoption association

Record the qualifying start before discovery/outcome, including the predeclared task acceptance reference. Append records actual observation/arrival time; a retrospectively backdated start after success cannot manufacture enrollment. Historical enrollment requires explicitly checked contemporaneous timing evidence. Scorecard as-of excludes later-observed evidence, with later evidence producing a versioned correction and immutable prior snapshots. Exact inspection binds public catalog origin and bundle digest. Deliberate selection records branch `new_install` or `existing_install` before use and explicitly associates that release with the selected closure/package/version, compiler bindings, runtime protocol digest and opaque instance reference. Compare exact root bundle/package pins and native compilation proof; comparing only runtime digests is insufficient. Do not retain closure, bindings values, grant payloads or instance/workspace IDs in the ledger.

For a new install, associate the existing install BEGIN/progress and its signed-reconciled receipt with the same chosen release and instance. For an existing install, verify the selected release/compiled protocol against the already installed signed instance and record deliberate selection; do not reinstall or invent a prior install event. A mismatch or missing release/proof join is quarantined/unknown. Native helpers must reuse existing inspection/compiler/progress/read validation rather than trusting a hand-written runtime-digest association or changing the journal. A useful result additionally joins accepted signed action/result evidence to the same instance/task and the task's declared acceptance. Adoption selection, install acceptance and useful result are separate facts.

## Full metric coverage and limits

Compute ACQ-01 through10 and the six fast windows from this same versioned event snapshot, with event window/as-of, numerator/denominator, mature/pending/lost/excluded/unknown, observation coverage and evidence references. Only externally evidenced eligible principals count; official seed/operator synthetic fixtures remain excluded. Missing denominators yield null, not zero population. Principal first-observed and proved newness remain separate.

Retention requires another genuine task/acceptance reference at7–14d or28–35d; early48h repeat stays separate. Publication24h needs receipt AND exact public visibility. Share24h/14d needs actual delivered exact reference preceding first start, evidenced distinct controllers and one primary referrer; mature recipients without starts remain in denominator. Supply-with-use requires a different evidenced downstream controller, not another key. ACQ-09 business/workflow/first attempt/recovery stay separate and missing call evidence is unverified. ACQ-10 reports instrumented/uninstrumented channel and join/identity/source/result coverage. Late evidence emits a new report/correction with observed-at; old reports remain available. No live external population is fabricated from local tests.
