# Per-client transport options (T086)

Native clients now carry one invocation-local `transport` object through their shared HTTP transport, including fresh reopens and secondary replay/read paths. Defaults remain15,000ms, OS trust roots, no added CA and the existing explicit proxy contract. Participant-selected local trust/resource choices do not alter workspace authority, signatures, source proofs, origin bindings, identity or protected profile/history schemas.

```json
{"transport":{"request_timeout_ms":15000,"additional_root_pem_files":["/public/example-ca.pem"]}}
```

`request_timeout_ms` is a positiveu64 in milliseconds, with `Instant::checked_add` checked before client creation. There is **no arbitrary24h ceiling**; platform-unrepresentable deadlines are rejected safely. This is per HTTP request (connect through response body), not a deadline for an entire multi-request SDK operation. CA inputs are public regular files: at most16 files,65,536 bytes/file and262,144 aggregate bytes. Metadata checks precede allocation; the opened file must also be regular, Unix opens nonblocking to prevent a raced special-file wait, and actual streaming uses remaining-bound+1 followed by rejection. Empty files, noncertificate/malformed PEM, oversized input and invalid paths fail closed without certificate contents in errors/logs. Every certificate bundle is parsed. Added roots merge with existing OS trust; hostname and certificate verification stay enabled. No verification-disable flag or mandatory global timeout/CA setting was introduced.

Explicit nested transport is accepted by Snapshot/Read, Owner and derived action/package/admission/coordination/format/attachment/recovery, invitation/private-grant receive, recipient enrollment, identity-directory and catalog configs. All constructor/reproof config paths carry the same object. KernelAccess has a backward-compatible `with_transport_options` builder. Native Python/Node kernel, recipient-enrollment and identity-directory methods gain an optional **final** `transport_json` parameter; existing positional calls retain defaults. Other JSON bridges receive the nested object. Pure Python/Node idiomatic facades are separately owned T087, not this package's implementation or HTTP claim.

CLI JSON configurations use the same nested object. Existing kernel, snapshot/read/private-read, recipient and directory flag selectors accept `--request-timeout-ms=N` and repeatable `--additional-root-pem-file=PATH`; Owner help documents JSON transport. Shared protected load_config preserves explicit transport with normalized defaults and resolves its relative CA paths against the selected config directory; omitted transport leaves the old origin/state_dir JSON shape intact. It validates options without opening CA files, creating state/identity or making requests. Direct constructors/ordinary CLI paths resolve relative CA inputs against invocation cwd. CA files are opened by client construction, not config discovery.
