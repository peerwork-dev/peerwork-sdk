# Historical Owner orphan package-stage handoff design

The current f828 `stagePackageMaterial` saves `package_stage_intents[key]` before calling `post()`; `post()` saves `pending[command_id]={path,body}` before HTTP. A crash between those saves leaves a marker with no signed packet. The old client, on later entry with the same material, deletes that marker and creates a new commit. Native attachment must not call this a retry of the marker command, infer that local pending absence proves no remote effect, or silently clear the marker.

The first supported orphan family is one-part PRIVATE wire-v3 STRUCTURED. A native no-POST inventory exposes the original marker command/source IDs, source hash/checkpoint, and SHA-256 of the complete protected TS agent-state file. Owner PEM and complete canonical SQLite intent snapshot remain separately hashed/rechecked and protected. The caller explicitly selects the original marker ID and inspected state digest. Before an immutable PREPARED row, complete configured-origin replay must prove the current signed PRIVATE Owner/key/policy/ring, the marker source checkpoint is exactly latest, and no corresponding signed stage operation exists. Mismatch refuses with no lifecycle/attachment or business effect. Quiescence of the old TS writer and any outstanding requests is a prerequisite; native locking does not lock the old client.

The selected marker is preserved in protected attachment history and reaches `ATTACHED_RESTRICTED` without a POST. Read/status remain available; ordinary action/install/format selectors return `ORPHAN_STAGE_UNRESOLVED`. It has an explicit `ORPHAN_NO_PACKET` local status, never ACCEPTED or rejected. The marker has hashes, not the original source material or a signed request. If the caller lacks the full material, the handoff reports `ORPHAN_MATERIAL_REQUIRED` and stays restricted.

`replan_orphan_package_stage` is a separate explicit write. It accepts full caller material and requires the native compiler to reproduce the marker's complete one-part source proof, including source ID/hash against the authenticated pinned source checkpoint. It rechecks that the current signed head/policy still equals that checkpoint. Before invoking the existing native PRIVATE stage producer, it persists a protected handoff mapping containing the original marker, new stage ID, new command ID, issued time, material digest, root/protocol digests and full-proof digest. The producer then saves the material and exact newly signed packet in its protected stage document before POST. A crash between mapping and producer save requires resupplying the same full material; later recovery reads only the protected stage document and reuses the same saved packet/ID. The producer checks the expected source ID and fixed command/time before any POST, including after a fresh replay. A signed replay of the exact new stage/part, not HTTP success, marks `ORPHAN_REPLANNED` and unlocks ordinary capabilities. The original marker and new-ID link remain in protected history.

This is a new authorized stage, because no original packet exists. It differs from pending-stage recovery, which preserves and retries an existing signed packet. Stale heads, policy changes, and uncertain/rejected POSTs retain the marker and new intent with an actionable unresolved status. Multipart prefix continuation and a general orphan disposition after source/material loss remain required beyond this one-part gate. No operator state edits, service DB uploads, or production cutover mutation are part of the fixture.
