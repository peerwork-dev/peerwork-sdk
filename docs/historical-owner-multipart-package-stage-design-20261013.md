# Historical Owner multipart package-stage design (2026-10-13)

Source: current TypeScript client `f828b6c50a0a58d1e718af90f653b214adcc3328`, especially `src/workspace-secure-agent.ts:172-197` and `src/workspace-protocol-package-source.ts:47-104`. Native base: SDK `5d2e25a`, `crates/runtime/src/secure_owner_attach.rs` and `crates/core/src/prepared_private_install.rs`. This is a design checkpoint, not an importer or service result.

The old client creates a full material proof before staging and writes one signed `secure.protocol-package.stage` ADMIN DELTA per part. Its marker records the base checkpoint, full material SHA/source ID, current part index and command ID. The marker is saved before the signed packet is stored in `state.pending`; each accepted part removes the pending packet before the marker is cleared. A marker with no pending packet can therefore denote an accepted part or an orphan with no packet. Its index alone cannot establish whether the entire source was staged. A marker with a saved pending packet must retain the original signed commit and ciphertext; any HTTP retry may create a fresh read proof, but must use the original commit/body/command ID.

The first bounded implementation will handle a **completed final multipart marker with no saved pending packet**. Parse the exact marker fields, map key, Owner/workspace and `part_index` within the source compiler's bound. Before an immutable attachment row or lifecycle import, fetch a complete origin-bound signed replay under the imported Owner identity and epoch ring. Require the base checkpoint as an ancestor, then exactly `N = part_index + 1` consecutive signed stage commits at base+1 through base+N. For each commit, verify command/action/context/actor/key/workspace/previous/policy, ADMIN DELTA, one signed part object with matching source checkpoint/source ID and index, and the authenticated commit hash/checkpoint. The final commit command ID must equal the marker command ID. Concatenate all N signed part texts, compile the entire canonical material at the authenticated base with `prepare_package_source_wire`, and require its material SHA/source ID and **complete** proof, part count, descriptors and canonical part objects to equal the signed range. The proof's part count must equal N. This prevents an intermediate part from being classified as a completed source, even when its own POST succeeded. Recheck the source files after the network proof and repeat the signed proof on resume.

The signed stage prefix may be followed by later authorized commits. The f828 verifier takes an explicit target checkpoint and validates a staged prefix inside a longer journal, so completion should use the exact base+N checkpoint rather than require the latest head to equal the final stage commit. Current replay, policy, Owner member and ring must still be independently authenticated before ATTACHED. Missing or pruned prefix proof fails closed; a later head never proves the old marker accepted by absence alone. The current one-part family remains supported by the same conditions.

A second fixture faults after an intermediate accepted part and requires no false complete classification/no ATTACHED; retain its exact marker and any remaining material for the later continuation lane. A valid later signed action after the completed stage can test the historical-prefix path separately without weakening the final-marker proof.

Required next tranche: for a pending part at index greater than zero, pair the exact saved signed packet with all authenticated earlier parts and caller-supplied full material; persist its original command/body in a protected native journal before an explicit retry, reconcile applied loss with zero retry, and continue subsequent parts under durable new IDs only after signed acceptance. For an orphan at index greater than zero, there is no original packet to retry: require explicit caller material, preserve the old marker, persist a distinct replan mapping/new packet before POST, and recover those same IDs after interruption. In both cases, ordinary action/install/format remain restricted while the prefix is incomplete or uncertain. Unavailable material, divergent head/policy, ENFORCE refusal and unresolved later parts require explicit retained status and disposition; they must never be silently cleared or relabeled accepted. The external TypeScript writer must be quiescent because the native lock cannot serialize it.
