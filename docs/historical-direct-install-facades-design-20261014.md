# Historical direct install facade scope

The next bounded package exposes the already reviewed completed-map runtime and exact retained-packet contract through Python sync/async, Node typed/native, and CLI. It follows combined runtime handoff `92960bf` and retained runtime product `40b6cdd`/final core candidate `ebe8dd7`; production edits and the single new installed cohort wait for root-coordinated core integration and source acceptance. The completed-map core is already main `c37c4ce`. These facades select caller-owned historical evidence; they add no recovery algorithm, authority or default source search.

Python uses the same explicit workspace/protected-source/Owner-pin parameters as existing historical methods. Completed inspection adds the caller-selected `instance_id`, `options_json` and `material_json`; completed attachment additionally requires that inspection's full `ts_state_digest` as a separate `expected_ts_state_digest`. Node uses the existing `HistoricalOwnerAttachmentInput` DTO plus corresponding selector/options/material strings and optional AbortSignal. CLI uses config/input/options/material files, an explicit selected instance for completed inspection, and the separate inspected full-state digest for attachment. Material stays in a file or wrapper memory, never CLI argument contents or output.

The completed DTO exactly matches `HistoricalDirectInstallCompletedInventory`: `ts_state_digest`, `instance_id`, `intent_hash`, `begin_command_id`, `begin_commit_hash`, `end_sequence`, `protocol_digest`, and `status`. Attachment returns the existing `HistoricalOwnerAttachmentResult`. The runtime verifies the selected completed END and current authority; there is no retained packet and no install POST or imported InstallRow. This facade must not reconstruct a replacement request.

Generic packet names are aliases for the existing BEGIN-named runtime methods and their existing native dispatcher. Existing BEGIN public names remain compatible. The selected command is the exact retained BEGIN, PAGE or END packet; pending inventory `command_id` and `original_commit_hash` refer to that selected packet. `pending_direct_install_command_id` in attachment results also refers to the caller-selected retained packet. The historical BEGIN ID stays in the imported installer row/progress; no new result field is invented. Completed-map attachment uses the reconstructed historical BEGIN ID because it has no selected packet. Tests must not conflate these meanings.

Ownership is limited to the two Python facade/native files, three Node facade/types/native files, CLI dispatcher/help, corresponding DTO exports/documentation, focused source routing tests, and an installed test harness/report. Core recovery implementation and historical proof predicates remain core-owned. All language paths must preserve strict selector exclusivity and expected-digest placement, cancellation routing, typed errors, explicit source/actor selection and protected-material handling. An aborted call may persist work and requires exact-ID recovery; aliases must retain that behavior.

Verification starts with affected four-crate compile, Python sync/async routing, Node routing/TypeScript consumer and CLI usage/input checks. One stable source archive and Linux glibc-2.28 installed cohort will then cover each interface independently, with separate protected roots and real pinned f828 services. Completed-map paths require exact selected inspection, wrong-selector/options/digest refusals without effects, explicit attachment, original source removal, protected reopen and authenticated ACTIVE instance/protocol/entrypoint readback, idempotent retry and no extra POST. Retained paths cover genuine PAGE/END pre-send and applied-loss packets, selecting their exact ID, full inspected digest, source removal, fresh-process exact recovery, unchanged method/path/body digest, matching original signed service commit and installer readback, and duplicate-free repeat. Existing BEGIN evidence is reused where source/config/environment still apply; aliases receive targeted routing coverage rather than a duplicate whole scenario.

Consumers use only installed public interfaces; service/operator oracles may query test fixture effects or record request hashes but cannot expose hidden native storage to consumers. Workflow correctness remains separate from signed business effects: these are deterministic operator tests, not natural-Agent behavior, external acquisition, public downloads or platform-matrix proof. Prior Agent attempts, operator timeout and Windows source-review correction remain preserved. No artifact rebuild or new actor starts before the runtime/facade contract and test source are frozen and reviewed.
