## Necessary propagation and smallest patch contract

Reuse TransportConfig rather than a parallel TLS client. A single serde/defaulted per-client `TransportOptions` should hold **request_timeout_ms** (positive checkedu64→Duration, default15000) and **additional_root_pem_files** (defaultempty; public certificate material only). Python snake_case, Node camelCase and CLI/config JSON must agree. Bound file count and total/per-file bytes before allocating/reading; native shared reader parses all supplied certificate roots or rejects malformed material, never logs contents, and merges roots with OS trust. Exact finite bounds should be fixed/documented with the implementation; no need to invent a key permission model for public CA certificates. Reject invalid/oversized/empty CA input and zero/overflow timeout before requests. Keep default behavior, redirect refusal and all signed-source/policy/origin checks unchanged. No danger-accept-invalid switch. Proxy compatibility stays explicit-config→SDK-env→direct.

Required config ownership is broader than only four read DTOs: Snapshot `SecureReadConfig`; latest `SecureReadProfileConfig`; Owner `SecureOwnerCreateConfig` and all derived action/package/coordination/format/attachment/recovery configs; Invitation `PublicDecisionConfig` including private-grant and subsequent reads; `RecipientEnrollmentConfig`; `IdentityDirectoryConfig`; `PublicCatalogConfig`; and KernelAccess. KernelAccess currently owns only origin/journal/identity/features/allow-http/authority (`kernel_access.rs:33–95`) and creates defaults on every reopen: add a default-compatible builder/config bridge and extend native Python/Node Kernel JSON dispatch plus CLI kernel options without breaking existing positional calls.

All production constructors must use one shared options→TransportConfig helper. Concrete default-producing sites to cover: `kernel_access.rs:87`, `secure_read_access.rs:146,274` (ordinary and inactive generation), `secure_action_access.rs:461`, `secure_owner_create.rs:813,893`, `secure_owner_attach.rs:803,3800,4487,5113`, `secure_private_install.rs:1182,1729,1944,3200`, `secure_owner_format_transition.rs:432`, `secure_private_grant_read.rs:111`, `secure_recipient_enrollment.rs:505,728`, `secure_identity_directory.rs:196`, `public_catalog.rs:167`, and production public-install/admission/decision constructors. Audit derived config literals in `secure_read_profile`, Owner profile selection, coordination and invitation/grant continuation: **fresh reopens and second pinned replay must retain the same caller options**, not silently default. No persisted ProfileDocument/history or origin/identity pin rewrite is required: options are invocation-local; callers explicitly reselect them on future process opens. Preserve raw bound origins and lifecycle canonical-origin validation separately; a helper that merely canonicalizes a URL should not unexpectedly read selected CA files or make requests.

Public process settings can be useful compatibility inputs (the existing proxy opt-in and dependency Linux CA env), but making timeout/CA global-only would lose independent caller budgets/trust choices. Do not replace the per-client contract with mandatory global state. CLI should accept equivalent JSON config fields and explicit flags only where its existing selector supports them, with help and safe errors; no implicit wrapping or grant defaults.

## Smallest next actual regression

A fresh local HTTPS fixture with a generated test CA and a leaf valid for localhost, plus the existing public catalog GET route, is sufficient and has no business POST/state requirement. From each coherent public interface: (1) absent extraCA rejects, (2) explicit bounded CA succeeds with exact response, (3) same CA but origin127.0.0.1 against localhost-only SAN rejects hostname mismatch, (4) explicitly short timeout against a controlled delayed HTTPS GET refuses without verified result, then ordinary selected-timeout GET recovers. Assert no POST and capture safe error code/status/target only. Add cheap malformed/oversized CA, zero/overflow timeout, config propagation/reopen and default15000 checks. A small low-level Rust HTTPS test can discriminate trust independently; it cannot replace public facade acceptance. Reuse accepted proxy evidence if unchanged. No system trust installation, verification-disable flag, external endpoint or private key disclosure is necessary. Native Windows/macOS trust-store execution remains open.
