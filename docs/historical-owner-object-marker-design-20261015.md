# Marker-only object-source recovery (T018)

The dedicated native `object_stage_intent_candidates` returns redacted workspace/instance/marker SHA256/options hash/protocol/part count/optional orphan-command provenance from protected source. Candidates are advisory; `inspect_object_stage_intent`, `attach_object_stage_intent` and `recover_object_stage_intent` require the explicit canonical marker hash plus the existing workspace/Owner/source input, complete caller options/material, and authenticated signed replay. Existing selected-packet methods still accept only original 43-character saved commands. Marker selection is not a command or a missing signature.

Version2 protected plans retain exact original state/PEM/intents/options/material and distinguish the marker-hash selection from version1 saved packets. No pending packet may coexist. Signed source-floor proof and exact contiguous object-part operations reconcile the optional orphan ID: an accepted ID must be this source's exact latest part at the saved floor or one sequence beyond; an absent ID is never reused. New native tail packets have distinct random IDs and are saved/reverified before POST. Only complete authenticated SOURCE permits the distinct native BEGIN; signed END gates acceptance. Reload repeats current PRIVATE Owner/key/epoch, full material/compiler, original source and each saved native packet proof. Source bytes remain intact; generic import remains excluded.

The genuine four-part producer hooks public `save()` after durable writes at marker creation, command-before-pending, and post-response pending cleanup. The latter has an already accepted command without a pending packet. Each native gate preserves source, removes the original source before reopen, verifies durable per-part reopen, original orphan non-reuse, complete install/readback and no-effect repeat. Thin Python/Node/CLI marker routes are a separate follow-on; no new installed cohort is built here.
