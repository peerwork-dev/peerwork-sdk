# T104: PRIVATE operation depth discriminator

**Finding:** the relevant PRIVATE plaintext boundary is **2,048 levels, not 64**. The source supports a narrow candidate that can distinguish native replay from the reference path, but no runtime regression was run here.

For PRIVATE commits, the reference client canonicalizes the full operation and encrypts those bytes as `payload.body`; the signed outer commit therefore contains the shallow sealed-content envelope, not the deeply nested operation. `canonical()` in the reference crypto source has cycle/type checks but no explicit depth ceiling (`workspace-secure-crypto.js:54-84`). `createCommit()` seals `encodeCanonicalJson(input.operation)` for PRIVATE visibility (`workspace-secure-client.js:682-696`), and `verifyJournal()` decrypts, `JSON.parse`s, and canonical-roundtrips that plaintext (`workspace-secure-client.js:358-369`). This differs from the prior clear PUBLIC case, where the deep value remains in the signed clear envelope and encounters service canonicalization before native replay.

The reference interpreter leaves an action body unvalidated when the protocol has no `inputs` contract (`workspace-interpreter.js:82-85`). The frozen `wiki.create` action has no `inputs` contract and its effects select only `title` and `body` (`protocols/wiki/protocol.source.json:39-80`). The reference secure engine preserves the complete caller body in the ACTION operation after interpretation (`workspace-secure-engine.js:165-172`). Thus an otherwise valid PRIVATE `wiki.create` body with ordinary string `title` and `body`, plus an unused deeply nested extra property, is a source-backed candidate: the selected fields are validated while that extra subtree is neither selected nor traversed by the interpreter.

Native replay decrypts PRIVATE content and parses the plaintext with `parse_wire_json_js_bounded(..., 2048, MAX_CONTENT_BYTES)` (`crates/core/src/secure_replay.rs:1738-1749`, `MAX_CONTENT_BYTES` is 16 MiB at line 33). Secure-artifact canonicalization also uses a 2,048-depth limit (`crates/core/src/wire_json.rs:223-236`). The interpreter's 12-level `safe_value` bound applies only to values it actually materializes; the unused extra body property is skipped when there is no input contract (`crates/core/src/interpreter.rs:584-608, 1104-1113`). Therefore a candidate with that extra subtree at depth 2,049 can pass the reference-side construction path but be refused by native plaintext parsing. This is not a native 64-versus-reference-48 case; it is a candidate 2,048-level PRIVATE plaintext boundary.

The smallest meaningful follow-up, if authorized, is one genuine PRIVATE action through the existing reference client using the frozen `wiki.create` protocol, with only an unused extra body property crossing depth 2,048. Keep the visible title/body ordinary. Observe reference preparation/encryption and service acceptance separately from native signed-read/replay. A source-only conclusion does not establish that the JavaScript runtime can serialize the chosen depth or that service/runtime gates accept it; preserve those as explicit outcomes if that focused regression is later run.
