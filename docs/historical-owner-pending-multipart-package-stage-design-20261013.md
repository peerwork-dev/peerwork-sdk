# Historical Owner pending multipart stage: design checkpoint

This is a source-backed design, not an implemented importer or service result. Native base is SDK `5e5b326a205191707f768c5da32cacc813193284`; the historical client is f828 `f828b6c50a0a58d1e718af90f653b214adcc3328`. The current native parser refuses a saved package-stage packet whose marker `part_index` is greater than zero (`secure_owner_attach.rs::parse_pending_package_stage`). Its sole-part core importer derives complete material from the packet's one decrypted part; that derivation cannot prove a multipart source. The f828 client instead creates the complete proof from caller material, saves a stage marker and then an exact pending `{path,body:{commit}}` before posting each part (`workspace-secure-agent.ts::stagePackageMaterial`, `post`). A subsequent request may use a fresh read proof; its original signed commit, ciphertext and command ID must remain unchanged.

The selected multipart path requires complete caller-supplied material **before PREPARED**. An explicit material-bearing inspection/attach call retains the existing selected command ID and inspected full TS-state-file digest. The native preflight compiles canonical material against the marker's authenticated base checkpoint. It requires the complete source ID, source SHA, part count and every descriptor to match the marker and the source compiler's 128-part/resource bounds. The origin-bound complete replay must contain the exact base checkpoint and consecutive, authenticated earlier stage commits for indexes `0..part_index`: each signed ADMIN DELTA has the same Owner/workspace/policy/source, correct previous/hash/sequence, and one full canonical part equal to the compiled part. It must then verify the original saved packet at the current index with `verify_saved_private_package_stage`, using caller material, the base and authenticated predecessor checkpoints, signed policy, original command/issued-at, Owner signing key and epoch key. The decrypted object, context, signature, ciphertext, source and current part all have to match that plan. If the packet is already applied, only its exact commit hash and operation in complete signed replay prove acceptance; if unapplied, the replay must still end at its exact predecessor. A later divergent head refuses selection. Current PRIVATE Owner/member/policy/ring authority is checked separately from historical-prefix proof. Recheck TS state, Owner PEM and SQLite snapshot after the network replay and before durable PREPARED, while holding the native recovery lock. The old TS writer remains a quiescence prerequisite.

Save the validated full canonical material and original packet first in an attach-scoped **quarantined protected plan**. It is not a `StageRow` and is not discoverable or executable by ordinary staging APIs. Its deterministic key is derived from the authenticated workspace/source snapshot/command selection; the plan itself binds those values, original commit hash, part index and full proof. The future imported stage ID is also fixed and saved in this plan before any StageRow is created, so a crash between its save and attachment-history linking cannot generate a second ID. Under the native root lock, an exact repeated attach can find and reprove the same inert plan after a crash before PREPARED. An incompatible existing plan is a conflict; never recursively delete an arbitrary path or guess that stale material is safe to clear. The plan also contains protected exact copies of the bounded TS state, Owner PEM and checked SQLite snapshot, each independently digest-bound to the selection. Store large state/material in separate protected files with per-file and aggregate bounds so the 64 MiB state-store limit does not become an accidental combined cap. Write an exact, protected manifest **last** after all copies are durable; an incomplete copy cannot be treated as a plan, and cleanup may touch only an owned, validated plan path. Recheck all three original sources after saving the plan and immediately before writing an immutable PREPARED row that references the plan digest. Before PREPARED, it conveys no lifecycle authority and no POST path. After PREPARED, fresh process recovery may use these protected copies if the originals are gone; if original files are still present but their digests changed, refuse the divergence rather than ignoring it. Re-prove copied source, Owner key, packet, full material and origin-bound signed replay on resume. The separate source byte digests bind the caller-selected files and snapshots but do not prove those three files originally belonged together; that pairing remains an explicit caller/quiescence precondition. This avoids placing up to 8 MiB of material inside the 2 MiB attachment-history document. Material and keys are never returned by inventory/history.

Only after PREPARED is durable and the source/Owner/proof are rechecked may runtime create or link an imported `StageRow` with the exact historical signed prefix and original pending step. The row carries explicit attachment provenance and remains quarantined from ordinary `stage_history`/`continue_stage`; only a dedicated root-locked recovery operation can drive it while attachment is restricted. The history row binds its exact stage ID/digest before any POST. A crash after PREPARED but before the StageRow save reconstructs the same row from the quarantined plan; a crash after the StageRow save reuses its exact packet/IDs. Subsequent parts use the existing producer's durable step-before-POST ordering, and an ordinary stage selector does not become available until the full signed source is complete.

Import the previously signed prefix steps and the exact original pending step into a protected staging row before any POST. Historical accepted steps can be reconstructed as canonical `{commit:...}` envelopes from authenticated signed replay; that is not a claim to reproduce their original HTTP serialization. The original pending envelope comes from the saved TS body, not a re-signed or re-encrypted packet. Attachment may become `ATTACHED_RESTRICTED` with the complete material plan and original packet protected, but action, install and format selectors remain blocked until **all** parts are signed and the complete package source proof verifies. Read, safe status and explicit stage continuation remain available after the old source is removed. A first explicit continuation checks replay for exact original acceptance and makes zero POST if applied; otherwise it may POST the same saved body/ID only when authenticated current head, policy and epoch match the packet's predecessor. Any later part is authored only after the preceding part is signed; each new ID, issued time, packet and digest is durably saved before its POST. Repeated continuation, cancellation and reopen use those same bytes and IDs. Only full signed completion changes the restricted status. An HTTP 2xx, 409 or missing packet in current local state alone never proves accepted/rejected or nonapplication.

The narrow first real fixture should use f828's public stage API with canonical material split into at least **three** parts, stop at index 1 after saving its exact pending packet, and exercise both applied-response-loss and pre-send paths. The third part forces native authoring of a distinct later packet and tests its durable ID across cancellation/reopen; a two-part index-1 fixture alone would test only the old final packet. Assert prior signed part equality, original command/commit hash and ciphertext preservation, no POST on applied reconciliation, exactly one original-ID submission on pre-send, durable later IDs, complete signed proof, restricted selectors before completion, source removal/reopen and no duplicate commits on retry. A wrong material/source/command selection must fail before PREPARED/lifecycle/POST. This test is scripted runtime behavior, not evidence of Agent instruction compliance or installed facades. Unavailable caller material, pre-packet orphan markers, ENFORCE/stale disposition, and multipart orphan continuation remain separate required cases; the current completed-final-marker proof does not close them.
